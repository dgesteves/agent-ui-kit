Unified or split review of agent edits with word-level highlights and per-hunk accept and reject. Give it the old and new contents of each file, or a unified `patch` when you only have the diff, and it computes the hunks. J and K move between hunks, A and R decide (and move on), U resets, Shift A and Shift R decide everything, and ⌘ or Ctrl + Enter applies.

`onSubmit` receives each file with only the accepted hunks applied (`content`), with the ids of the hunks that were accepted, rejected or left pending; unreviewed hunks are left out of the content. That makes it a client-side tool result: send it back with `addToolOutput` and the agent continues from the files as you applied them, as [the quickstart](/docs/getting-started#render-a-run) does. It fires once per set of decisions: a double click or a repeated ⌘ or Ctrl + Enter sends one review until a decision or the files change. Files compare by content, so an inline `files` array does not re-arm it.

The same work runs on the server too: `parseFileChange`, `applyHunks` and `computeReviewResult` are in `signoff-ui/core`, with no React. Long changed lines skip word-level highlights rather than stall; a full rewrite of a large file is slow, as [Performance and limits](/docs/limits) measures.
